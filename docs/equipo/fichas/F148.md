  `act:closerMove` cuenta (620 de media en arcos). Ninguna llamada de `REPOSITION_CLOSER` encontró un camino en curso
  que acabe a ≤ 3 bloques del nuevo `spot`. Los datos no separan las dos causas: camino ya terminado (`nav.isDone()`)
  o destino que se movió > 3 bloques. 1.er fallo de esta capacidad: una ficha de medida está permitida (regla 8 cuenta

  se para, así que el coste es "un camino nuevo por llamada" inevitable con este `moveDue`; o **FAR** — el `spot` salta
  más de 3 bloques entre llamadas (el blanco se mueve o cambia), así que el umbral de reuso está mal puesto.
- Cambio (Java, **solo sim**, solo contadores; misma bandera `Tactics.simCloserReuse` / etiqueta `perf:closerReuse`;
  sin la etiqueta, código de hoy intacto). En `case REPOSITION_CLOSER`, dentro del bloque `if (simCloserReuse)` de
  [[F144]] (`Tactics.java` ~l. 399-411), sin cambiar qué se salta:
  1. si `nav.isDone()` → `SimProbe.count(guard, "act:closerDone")`;
  2. si no está hecho pero `getTargetPos()` es null → `act:closerNoEnd`;
  3. si hay `end`, con `d = sqrt(dx*dx + dz*dz)`: `d ≤ 3` → `act:closerReuse` (como hoy, y `return`); `3 < d ≤ 6` →
     `act:closerFar6`; `6 < d ≤ 12` → `act:closerFar12`; `d > 12` → `act:closerFarMax`.
  4. `act:closerMove` se queda como hoy (toda llamada que no salta).
  Nada más: ni umbral, ni `moveDue`, ni `MOVE_EVERY_TICKS`.
